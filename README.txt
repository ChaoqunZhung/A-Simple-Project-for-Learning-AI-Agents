从零到会用 Agent：一条看得见、能动手的科研助手入门路线
========================================================

欢迎来到 Research Agent！

这个项目想带新手理解一件事：Agent 不只是“会聊天的模型”，而是一个能理解目标、
选择工具、观察结果、再根据证据完成任务的程序。你可以从一个问题开始，逐步看清
模型、工具、记忆和多 Agent 协作是怎样连起来的。

本指南聚焦“流程怎么设计、如何入门”。安装环境、配置模型和运行命令请看同目录下
的 README.md。


一、先记住这条主流程
--------------------

用户提出问题
    ↓
Agent 读取问题和当前会话上下文
    ↓
模型判断：直接回答，还是需要调用工具？
    ↓
需要工具时，Agent 选择工具并生成结构化参数
    ↓
程序校验参数，再由对应工具执行
    ↓
工具把真实结果交还给模型
    ↓
模型根据结果继续工作，或整理证据并回答
    ↓
保存本轮对话，供同一会话后续参考

关键点：模型负责理解、选择和组织；程序负责校验、执行和返回真实结果。
工具没有执行成功，就不能把它说成成功；没有证据支持的内容，也不能伪装成事实。


二、把 Agent 想成一位会使用工具的研究助理
-----------------------------------------

1. 大脑：大语言模型
   理解问题、决定是否需要工具，并根据工具返回内容组织回答。

2. 工作流程：Agent 主循环
   接收问题 → 请求模型 → 处理工具调用 → 把结果交回模型 → 整理最终回答。
   如果工具调用次数达到上限，流程会停止继续调用并要求模型说明限制。

3. 双手：工具
   - calculator：完成受限的基础数学计算。
   - python_calculate：对示例 CSV 做受限科学计算。
   - file_tool：读取 data/ 下允许的本地数据文件。
   - paper_search：查找本地 PDF 中的相关片段，并返回文件名和页码。
   - web_search：检索互联网资料并返回来源链接。
   - MCP 工具：可选的外部工具接入方式。

4. 工作笔记：会话记忆
   按 session_id 隔离保存最近的对话。它只存在于当前进程内；程序重启后会清空。

5. 合作团队：多 Agent 编排
   Planner 根据问题安排研究或分析任务；独立任务可以并行执行；依赖已有结果的任务
   会等前序任务完成；最后由 Synthesizer 汇总并说明证据和局限。


三、新手推荐学习路线
--------------------

第 1 步：先运行，再观察
按照 README.md 完成 Python 环境和模型配置，启动 CLI。先问一个不需要外部资料的
简单问题，再尝试输入 /clear 和 /exit，熟悉一次对话从哪里开始、如何结束。

第 2 步：看懂一次工具调用
提问：“请读取 example.csv，计算 x 的均值和样本标准差。”
观察 Agent 如何选择 python_calculate、工具如何返回计算结果，以及最终回答如何
区分计算结果和解释。试着把问题改成中位数或相关性，比较工具输入和输出。

第 3 步：区分事实、计算和分析
要求回答按“事实与证据、计算结果、分析与局限”组织。思考每句话来自哪里：
是文件中的数据、工具计算结果，还是模型的解释？小样本结果有哪些局限？

第 4 步：体验检索增强生成（RAG）
将自己有权使用的文字型 PDF 放进 data/papers/，询问其中的方法或结论，并检查回答
是否给出文件名和页码。RAG 的重点不是“模型记住了论文”，而是先检索相关片段，
再让模型依据这些片段回答。

第 5 步：体验多 Agent
使用 CLI 的 multi 模式，提出一个同时涉及文献、数据或最新网页信息的问题。观察
Planner 如何拆分任务，哪些任务可以并行，以及最终综合如何处理证据和缺口。

第 6 步：读代码，做一个小改动
建议按以下顺序阅读：
  main.py                 命令行入口
  agent.py                单 Agent 主循环、模型请求和工具调用
  tools/__init__.py       工具定义、参数校验和分发
  tools/                  各具体工具实现
  memory.py               会话历史
  rag.py                  PDF 检索
  multi_agent.py          多 Agent 任务规划与综合
  api/server.py           HTTP API
  tests/test_project.py   离线自动化测试

从一个小问题开始：增加一个清晰的工具说明、改进错误提示，或给现有流程补一个测试。
先看现有实现和测试，再改代码；最后运行测试，确认旧流程没有被破坏。


四、理解一次请求中的“观察—行动—再观察”
----------------------------------------

Agent 的工具循环可以这样理解：

观察：读取用户目标、会话上下文和目前已有的证据。
行动：选择一个工具，并给它符合规则的参数。
再观察：读取工具的实际返回结果，判断是否还需要下一步。
完成：有足够依据时回答；证据不足或工具失败时，明确说明限制。

这也是 Agent 和“只生成一段文本”的聊天体验之间的重要区别：Agent 可以对外部
信息采取受控行动，并根据行动结果调整后续步骤。


五、设计一个可靠的 Agent 流程
------------------------------

1. 目标明确：每个工具解决一种清晰的问题。
2. 输入可校验：参数有类型、范围和允许值，不把模型输出直接当成可信命令。
3. 结果可追溯：保留来源、页码、URL 或计算结果，让回答能说明依据。
4. 失败可见：超时、空结果、缺少密钥和无效参数都应明确报告，不能伪装成成功。
5. 权限最小：工具只能访问完成任务所需的数据；不要给 Agent 不必要的系统权限。
6. 步骤有界：限制输入大小、工具调用次数和运行时间，避免任务无限继续。
7. 结论诚实：区分来源事实、工具计算和模型分析，明确写出证据不足与适用范围。
8. 测试离线流程：优先用模拟模型和本地示例数据测试，不依赖真实 API 密钥。


六、项目中如何找到这些设计
--------------------------

agent.py
  核心单 Agent 循环：把用户问题交给模型，校验并执行工具调用，再将工具结果交回。

tools/__init__.py
  集中定义工具、检查工具参数，并把合法请求交给具体工具实现。

memory.py
  管理按会话隔离的对话历史和容量限制。

rag.py 与 data/papers/
  处理本地 PDF 的发现、文本提取、分块和检索。

multi_agent.py
  按问题类型规划任务，安排专员执行并由综合 Agent 汇总。

api/server.py 与 main.py
  分别提供 HTTP API 和交互式命令行入口。

skills/
  为科研工作流程提供可重复使用的指导，例如文献综述、数据分析和网页证据整理。

tests/test_project.py
  覆盖工具、检索、记忆、Agent 和 API 的离线测试。


七、动手前的安全提醒
--------------------

- .env 中的 API 密钥只用于本地配置，不要提交到 Git 或粘贴到公开页面。
- data/papers/ 中的 PDF 默认不纳入 Git；上传前务必确认自己有分享和发布权限。
- logs/、虚拟环境和 Python 缓存属于本地运行产物，不应作为项目源码发布。
- 受限 Python 计算工具不等于经过安全审计的操作系统沙箱；不要把它当作执行恶意代码
  的安全边界，也不要在未做隔离的情况下对外开放服务。
- API 默认没有用户认证。公开部署前，应先设计认证、限流、数据隔离和运行环境隔离。
